Benchmark

Questions a teammate would actually ask

Even a simple workplace question can mean finding the relevant channels and direct messages, recovering context from long discussions, inspecting repository state, reconciling stale or conflicting evidence, and synthesizing across sources. Single-shot retrieval over a flattened corpus is often not enough.

AS58tasks

Agentic Search

Search for specific facts across Slack channels, GitHub repositories, Google Docs, and sometimes the open web. Some queries require tracking the project timeline and the order of GitHub operations. Answers are short and easy to verify.

ExampleWhat are the currently remaining TODOs for Ryan in the tool-bench-langvar project?

HA48tasks

Hallucination

The right move is to abstain, and to say why. To pass, the agent must both decline and identify the correct reason:

  • Answer unknown: e.g., results on a benchmark the project never used
  • False premise: e.g., predictions built on the opposite of what was posted
  • Context restriction: the answer lies outside a time window the query sets

ExampleI remember that for our prompt variation project for BFCL, changing return format to typescript + tool call tags would decrease the performance for gpt-4o, could you find how much the decrease is?

SU14tasks

Summarization

Summarize toward a goal, such as a recommendation letter for a research assistant who worked across several projects. The agent must search comprehensively and stay faithful. Each task is graded against a human-written checklist, with partial credit per item.

ExampleI'm trying to write a recommendation letter for Marcus for his PhD application. Could you summarize his research contributions?

CI20tasks

Circumstance Inference

Identify who matches a circumstance, such as a free-rider, or two collaborators syncing offline without telling a third. Each query gets its own modified workspace history, with the signal spread across many messages rather than any single one.

Exampleone of our team keeps taking credit for someone else's work. who's the credit-stealer and who's getting taken from?

Agentic Search 58 Hallucination 48 Summarization 14 Circumstance Inference 20 140 tasks in total
Abstract

AI Agents are becoming digital coworkers that can browse the web, write code, run experiments, and assist humans over extended horizons. Yet existing benchmarks fall short of real knowledge work: many rely on synthetic data or isolated tasks, missing the complex, multi-party dynamics of collaborative projects, where critical information is scattered across conversations, code, and evolving decisions. Even simple workplace questions may require locating relevant channels and direct messages, recovering context from long discussions, inspecting repository state, reconciling stale or conflicting evidence, and synthesizing across sources.

We introduce SlackBench, a benchmark for evaluating agents on realistic research and engineering workflows that require joint reasoning over workplace communication and evolving repository state. Grounded in privacy-preserving reenactments of real academic research projects, SlackBench provides reproducible environments with realistic multi-party dialogue, evolving decisions, and corresponding code changes grounded in GitHub repositories and Google Docs. It contains 140 queries spanning heterogeneous-source agentic search, abstention on unanswerable or false-premise questions, goal-directed summarization, and circumstance inference over long conversations. These tasks are not reducible to static corpus question answering: agents must determine which conversations matter, traverse threads, inspect repository state, and synthesize evidence across communication and code artifacts. Across 33 frontier models and agent harnesses, the best system scores around 80% and most agents score below 66%, highlighting substantial headroom for improvement. SlackBench thus provides an extensible framework for evaluating agents in collaborative work environments.

Environment

Real research, reenacted for privacy

SlackBench does not release anyone's private chat history. Instead, humans and coding agents ran real research projects from scratch in a live Slack workspace, grounded in real repositories and documents. The workspace was then exported and cleaned by hand, preserving chronology, task dependencies, and how artifacts evolve.

  1. 1

    Run real projects in a live workspace

    Each channel is a research project started from a concrete idea, such as how sensitive tool-call accuracy is to prompt format. Humans act as project leads; coding-agent sessions (e.g., Cursor, Claude Code) act as research assistants with their own Slack and GitHub accounts.

  2. 2

    Ground every thread in artifacts

    Channels connect to GitHub repositories with project code and writing, and some to Google Docs such as meeting notes or IRB applications, shared in conversation the way real teams share links.

  3. 3

    Steer agents like teammates

    System prompts tell agents to communicate like human research assistants. Subtle hints in user prompts add the varied conversational dynamics of a real research group.

  4. 4

    Export and clean by hand

    Messages that sound too AI-like are rewritten, real API keys are replaced with fake ones, and hallucinated content is corrected against the repositories.

  5. 5

    Curate queries and answers

    Humans curate and verify the reference answers and grading rubrics for all 140 queries.

Evaluation setup

  • All runs use the Harbor framework for containerized agent evaluation.
  • Read-only tools. MCP servers for Claude Code, Codex CLI, Gemini CLI, Antigravity CLI, Grok Build, and Muse Code; an equivalent command-line wrapper over the same endpoints for Terminus-2 and OpenHands.
  • Medium reasoning effort and a 20-minute limit per task, unless an ablation says otherwise.
  • Scores are average pass rates over three runs; Overall is the unweighted mean of the four categories.
  • LLM judge (GPT-5.4). AS, HA, and CI answers are judged pass/fail against a reference answer and an optional grading guideline; SU answers earn partial credit per checklist item.
  • Agents also get terminal read, bash, and web search, since some questions need sources outside the workspace.

Findings

What 40+ experiments show

We ablate across models, harnesses, data-access interfaces, and reasoning effort, and check that the measurements themselves hold up.

01

A gap to humans remains, and it varies by category

Three researchers who did not build SlackBench, given the same environment and tasks and allowed to use AI tools such as Claude Code, reach 84.5% overall (95% bootstrap CI 77.0–92.0%). The best agent reaches 80.25%, and most agents score below 66%.

Per category the picture is mixed. The top agent is level with humans on Hallucination (90.28 vs. 90) and above them on Circumstance Inference (83.33 vs. 75), but far behind on Agentic Search (70.69 vs. 91).

Strong search also does not imply knowing when not to answer: OpenHands with GPT-5.5 passes 60.92% of Agentic Search tasks, yet trails Claude Code with Claude Haiku 4.5 on Hallucination.

02

Plain files beat MCP tools

Giving agents the exported workspace as files, so they can use grep, jq, and cat instead of Slack MCP tools, raised overall pass rates in every setting we tried, by 7.85 points on average. Codex CLI with GPT-5.5 gained 17.25 points on Agentic Search and edged past Claude Code with Claude Opus 4.7 overall.

CLI access also cut cost by 54% for Claude Code with Claude Opus 5.5, and token use by 21% on average for the other agents we traced. CLI agents read whole context directly; MCP agents lean on search_messages, whose metadata-rich responses inflate the prompt.

03

Cost and accuracy are only loosely linked

One full pass over SlackBench costs anywhere from under $1 to over $500, depending on model pricing and harness design. Muse Wonder scores 73.74 in Muse Code for about $143; the same model in Claude Code scores 3 points lower and costs more than $500.

Being near the Pareto frontier does not mean shorter trajectories: Claude Code with Claude Opus 5.5 averages 11.9 steps per task, while Antigravity with Gemini 4 Argon, the top scorer, takes more than 20.

04

More reasoning effort helps, with uneven returns

Moving from low to high reasoning effort raised overall accuracy for all five agents we tested. The size of the gain varies widely: from low to high, Claude Code with Claude Opus 4.7 gains nearly 19 points but Claude Code with Claude Sonnet 4.6 only about 4. Codex CLI with GPT-5.4-Mini gains 12 points from low to medium, then barely moves at high.

05

The harness matters, not just the model

The same model can land far apart depending on the agent harness around it. GPT-5.4-Mini scores 27.04 in Codex CLI but 12.82 in Terminus-2; Gemini 3.1 Pro Preview ranges from 38.80 in OpenHands to 46.28 in Gemini CLI.

06

Answer first, caveat later

All GPT models we evaluated are weak on Hallucination tasks. Faced with a false premise, they tend to give a specific answer first and only note at the end that it rests on a different premise.

Asked about the status of an OpenRouter issue, GPT 6.1 Sol opens with “Yes—the workaround unblocked the runs,” and only at the end notes that this refers to the Grok issue, without confirming that no such OpenRouter issue exists.

07

The measurements hold up

We manually reviewed all 264 judgments for Codex CLI with GPT-5.5 across all 140 queries, including rubric judgments for Summarization: the GPT-5.4 judge agrees with humans 95.8% of the time. Swapping in Claude Opus 4.7 or Gemini 3.1 Pro as the judge changes little; every pair of judges agrees on more than 95% of verdicts.

Our Slack tools also track the official Slack MCP server closely. On a filtered subset of AS and HA queries, scores are generally similar, with the official server slightly ahead in some settings, possibly because frontier agents have been tuned on it.

Some agents found the answer key. During development, agents had a private GitHub token that could also reach our SlackBench repository, which contains all queries and reference answers. In rare cases, agents navigated straight to it and read the answers, echoing recent findings on evaluation awareness in frontier models. We therefore do not release all reference answers publicly; they are available to researchers on request.

Failure modes

Where agents go wrong

We read agent trajectories by hand. The same patterns recur across task categories, and they point to concrete ways to improve workplace agents.

01

Insufficient global verification

Agents find a plausible answer, then check it only against nearby messages in the same channel, missing later evidence elsewhere. The answer is well supported locally but wrong globally.

02

Shallow proxy reasoning

Without direct evidence, agents fall back on proxies, such as ranking contributors by message volume, when another teammate did the harder work of building the pipeline.

03

Failure to recognize false premises

Given a question built on a false premise, agents fixate on the wrong assumption, keep searching under it, and often end up with a hallucinated answer.

04

Confabulation from planning artifacts

When something was discussed but never produced, agents treat planning threads, TODO items, or outlines as proof it was done, and stitch together a plausible answer.

05

Equating absence of keywords with absence of behavior

Finding no message that literally calls someone “irresponsible,” agents conclude the behavior never happened, despite a clear pattern of declined tasks, days of silence, and missed deadlines.

FAQ

Questions

Is SlackBench built on real Slack data?

Not on private chat logs. Each channel is a privacy-preserving reenactment of a real academic research project: humans and coding agents carried out the project in a live Slack workspace, grounded in real GitHub repositories and Google Docs. Around 35.0% of messages were written directly by humans and another 35.2% were substantially rewritten by humans, and the exported history was filtered by hand.

What can an agent access during a task?

Seven read-only Slack tools (list channels, read channel history and threads, look up users, search messages), fourteen read-only GitHub tools (search and read repositories, code, issues, pull requests, and commits), plus terminal read, bash, and web search. See Environment for the full list.

How are answers graded?

By an LLM judge (GPT-5.4). Agentic Search, Hallucination, and Circumstance Inference answers are short and judged pass/fail against a human-verified reference answer, sometimes with a grading guideline. Summarization answers are scored against human-written checklists, with partial credit per item.

On all 264 judgments for Codex CLI with GPT-5.5, the judge agreed with human review 95.8% of the time, and GPT-5.4, Claude Opus 4.7, and Gemini 3.1 Pro agree with each other on more than 95% of verdicts.

Why aren't all reference answers public?

During development, agents with a GitHub token that could reach our private SlackBench repository occasionally went straight to it and read the reference answers. To keep scores meaningful, we do not release all reference answers publicly. They are available to researchers on request.

How do I run SlackBench?

Experiments run on the Harbor framework, with a 20-minute limit per task and medium reasoning effort by default; we report the mean of three runs. Code and setup instructions are coming soon.

How much does a full run cost?

From under $1 to over $500 per pass over the benchmark, depending on model pricing and harness design. See the cost analysis.

How do humans do?

Three independent researchers who were not involved in building SlackBench reach 84.5% on average (91% on AS, 90% on HA, 82% on SU, and 75% on CI), with a 95% bootstrap confidence interval of [77.0%, 92.0%]. They used the same environment and tasks as the agents and were allowed to use AI tools such as Claude Code.

Can I contribute or report results?

Yes. SlackBench is designed as an extensible evaluation framework, and we invite the community to contribute new environments and queries. Reach us at huanzhimao@berkeley.edu.
